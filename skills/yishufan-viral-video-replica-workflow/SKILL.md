# 艺术范爆款短视频复刻工作流 v7.3

## 本版执行顺序

新生产先完整读取[V7.3导演核心](references/director_core_v73.md)。只有需要高密度反转、复杂连续广告或详细schema字段时，再读取[导演与留存编剧规范](references/director_retention_playbook.md)和[schema v5 创意与美术证据](references/creative_direction_v5.md)，不要默认加载所有说明。新生产使用schema 5并在合同声明`director_core_version=7.3`；旧合同只读复盘，不能改版本号冒充重新审片。

`事实与源图 → 03导演计划（故事+镜头+连续状态）→ 逐秒脚本与独立编辑 → pre-visual → 原创样张 → 分镜/提示词 → pre-generation → 经授权写表/生成 → 实际片逐帧复盘 → 合片/发布门禁`。

默认快路径只维护一个`03_director_plan.json`，不再强制创建内容重复的候选稿与结构映射文档。`08_replica_contract.json`负责资产、权限和机器门禁；`04_script.md`负责可读导演稿。某条信息只设一个权威来源，其他文件用ID引用，不整段复制。

用户指出成片差或提供生成结果时，优先取得实际视频，用“参考→脚本→输入图→提示词→实际输出”定位偏差；不得只看原计划就断言视频执行结果。保留失败项目作负样本，不覆盖原结果、刷高自评分或删错误来制造通过。

## 便携包路径

把“包含本 `SKILL.md` 的目录”作为 `SKILL_DIR`。本包已在 `vendor/watch/` 内置拉片、字幕提取和 ASR 后端，命令示例中用下面的便携路径：

```bash
SKILL_DIR="<包含本 SKILL.md 的完整路径>"
```

## 交付边界

默认交付参考证据、商品事实与视觉锁、`03_director_plan.json`、逐秒脚本、必要人物/分镜图、分段视频提示词、机器合同和生成前报告。用户只要求脚本或复盘时，不生成与结果无关的空模板、长候选文档或AI表载荷。

除非用户明确要求，否则不得生成视频、消耗积分、导出成片或发布。用户明确要求完整制作时，先通过生成前门禁，再完整读取[VidMuse完整制作分支](references/vidmuse_full_production.md)；没有真实证据支撑的内容标记为“创作推演”。

## 最小输入

- 对标来源三选一：真实视频、明确的历史爆款检索、用户提供的静态插画集。静态图只有视觉和内容证据，没有原视频时长、ASR或镜头顺序。
- 商品截图或详情资料；实物商品必须有足以锁定外形、比例、颜色、材质、结构和Logo的清晰产品图。只有卡券/权益页时不得虚构未展示的实物角度。
- 风格参考图或可作为风格证据的参考视频；没有独立风格图时，明确以原片为风格源，不得凭空补成通用“高级感”。
- 复刻模式与节拍密度；用户未指定且不同选择会改变结果时，只询问一次。

默认规格：9:16、中文普通话、每个生成片段1至15秒。写AI表时人物、分镜、音频和商品素材总计最多9个附件。高保真视频复刻跟随原片完整时长；原创机制/静态图混合模式由故事、桌读和粗剪确定时长，先以约30秒探索，不默认凑满三段45秒。压缩等待和重复交易，不删必要铺垫与兑现。

## 内置爆款向量案例库（按需）

只有用户只给卡券/商品、明确要求历史爆款，或当前案例需要读取失败教训时才检索；已有明确参考时不把案例库变成额外必做步骤。用完整需求检索，不只输入商品名：

```bash
python3 "${SKILL_DIR}/scripts/viral_library.py" search "<商品+人群+场景+机制+视觉>" --top-k 5 --out "<项目>/00_historical_match.md"
```

完成真实复盘后才用`viral_library.py build --workspace <工作区>`刷新本地库。默认不索引私人聊天，不把API Key、Cookie、原视频或本机绝对路径分发。执行规则：

- `decision=insufficient_match`时停止强行套模板，改为请求新参考视频或只做原创机制推演。
- `quality_status=blocked`的案例不得复用其脚本、提示词或分镜；若存在可信原片分析，只能复用`reference_analysis_only`，同时读取其QC复盘作为负面门禁。
- `quality_status=unknown`不等于成功，只表示历史材料没有发布级结论；进入本次创作后仍须通过所有质量门禁。
- 种子库不携带原视频或原机器资产；只能引用库内存档的时间码、哈希、分析、脚本和失败教训，不得声称本轮重新观看了原视频。
- 用户本地库即使显式包含历史聊天，聊天权重仍低于工作区正式产物，不得替代拉片证据。
- 检索只负责提供机制和失败教训，不拼接旧脚本。正式block或用户拒收优先于历史allow；未知质量不能作为成功生产模板。

用户提供了新参考视频时，仍可用该库检索相似案例与失败教训作为辅助，但主参考身份、时长和SHA-256必须以本轮真实读取的新视频为准。

## 阶段零：锁定模式、视觉世界和素材身份

生成脚本或分镜前先输出：

```text
本次模式：高保真视觉复刻 / 爆款机制迁移 / 商业混合复刻
节拍密度：跟随原片 / 标准密度 / 高密度反转
制作范围：素材包 / AI表交付 / 完整视频
运动类型：参考片主导 / 剧情表演 / 连续运动广告
推断理由：
视觉世界硬约束：
```

完整读取 [references/三种复刻模式.md](references/三种复刻模式.md)。只能执行一种模式。用户明确指定的媒介、IP方向或画面世界是全局硬约束，不因“允许替换人物/场景”而失效；例如历史艺术化CG不得自行改成现代真人言情。

运行后端前回读用户本次提供的绝对路径或URL。禁止根据相似文件名选择其他素材。

## 阶段一：运行证据后端

完整操作见[后端契约](references/backend_contract.md)。静态插画逐张查看、绑定SHA与用途，不运行ASR、不伪造原片时间线；真实视频才运行：

```bash
python3 "${SKILL_DIR}/scripts/configure_asr.py" --check
python3 "${SKILL_DIR}/scripts/prepare_reference.py" "<参考视频>" \
  --out-dir "<项目目录>"
```

真实视频必须逐张查看固定0.5秒时间线、前3秒和反转簇密集帧；`watch`最高2fps，不称为30fps全编码帧审查。输出锁定SHA、时长/画幅、镜头表、双ASR及分歧。ASR不证明说话人身份，需结合字幕、口型和动作。关键音乐/音效单列时间码；抽出的原声是混音轨，不称为纯音乐。

## 阶段二：提取机制、事实表与产品/风格双锁

必须回答：第一秒为什么停留、为什么继续看、初始误判是什么、何处改变权力/因果/道具含义/空间真相、商品为何成为剧情答案、最后3秒为何值得看完。

切镜、换角度、重复爆炸或持续喊叫不算反转。高密度反转仅用于已测出的反转簇；簇内每秒至少新增一个有效变量，每2至3秒升级一个层级，且后一变化由前一变化造成。

商品事实表至少包含商品名、售价、权益、适用门店、售卖期、可用期、核销方式、限制和退款规则。每项标记素材来源与确认状态。不得把资格券写成免费商品，不得补写看不清或未提供的价格、数量、日期和限制。

同时创建`02_visual_lock.md`：

- 产品锁：列出每张产品参考资产的相对路径、SHA-256和用途；逐项锁定外形、比例、颜色、材质、结构和Logo。没有证据的侧面、背面、接口、包装文字等统一执行`do_not_invent`。
- 风格锁：从风格参考或原片提炼光线、色彩、构图、镜头语言、人物、场景和材质质感，生成唯一`lock_id`和一段可复用风格提示词；每个Clip提示词必须逐字带入该提示词和`lock_id`。
- 禁用项只记录本次素材和用户明确要求的冲突风格。原片本身是霓虹或赛博朋克时不得套用通用禁令。

这一步只锁证据，不构思创意。产品参考资产复制进项目并绑定哈希，不把AI推测图冒充原始产品证据。

另拆六个可见轴：主辅色面积/冷暖与饱和度、线条与平涂/晕染、纸纹强弱、面部比例与上色、空间组织、人物活动密度。不得把所有传统手绘自动译成低饱和黄旧纸。人物设定页白背景不能拉低场景主色统计；数值只诊断漂移，不替代美术判断。

“不直接使用原插画”默认是不把原图当成品，不等于禁止将原图传给模型作`style_only`参考。分别标注`style_only/layout_reference/character_identity/product_fact`。复现画法和色彩关系，重做人物、建筑形体、具体构图与事件；不能承诺只换脸换楼就绝对无侵权风险。

## 阶段三：创意室竞争与桌读准入

禁止看完参考片后直接写逐秒脚本。先把参考片拆成机制DNA：开场钩子、观众问题、初始误判、冲突发动机、反转机制、情绪回报和结尾记忆点。这里只继承传播机制，不抄表面台词。

默认在`03_director_plan.json.concepts`写3套真正不同的概念；每套只保留一句故事、核心冲突、商品作用、结尾和淘汰理由。若三案已有明显优劣，不为凑篇幅补长篇自证或另建`03_candidates.md`。只有用户明确要求大型创意竞标时才扩写到5至10案。

入选后立即落到`clips[].beats`。每拍必须有观众问题、新信息、可见动作、前因、入场状态、出场状态、事件阶段和镜头目的。默认每个15秒Clip最多3拍、2个有声回合；一个主要人物动作配一个主要摄影机动作。复杂动作拆拍，不用长提示词强迫模型同时完成退钱、递样、入口、转身和口播。

必须由未参与该稿创作的独立审阅者或真实用户只检查四件事：最可能划走的秒点、因果是否成立、动作是否能看懂、结尾是否兑现。结果写入绑定脚本SHA的`06_creative_review.json`。硬否决：无动机转向、道具无来源、完成动作重复上演、旁白替代关键动作、结尾未兑现或违背场景承诺。分数只作相对比较，不是准入证书。

桌读同时做商品删除测试：删除商品后失去什么到店动机或选择依据？商业关联弱就退回，不要求每个笑点都依赖价格。机器门禁只验证材料和准入条件，发布后的前三秒留存、完播和互动数据才验证传播结果。

## 阶段四：导演计划、状态连续和唯一兑现

先把原片每一次因果、权力、道具含义、空间真相和循环关系写成按时间排序的`Rxx`节拍账本。高保真模式下，责问→误判→攻击→道具揭示→赔罪→二次误操作→空间揭示→结尾循环等相邻因果节点不得合并、换序或删除；商品只能进入用户明确允许替换的位置。

统一写入`03_director_plan.json`，建立唯一链路：

```text
R01（原片证据）→ S01（新片节拍）→ B01（分镜）→ P01（视频提示词）
```

有视频参考时每拍填写对标时间码、心理/视觉功能、必须保留、允许替换、分镜和提示词ID；静态插画没有时间码，只绑定源图ID与画法用途。不得用“感觉一致”代替可验收事实。

`state_out`必须逐字段等于下一拍`state_in`，包括主角ID、左右手、道具持有者、位置、视线、动作阶段和群众签名。跨Clip也一样；主角暂时不在画面仍记录其持续状态。钱袋、小碟、人物位置或群众数量无交代跳变都阻断。

同一`action_event.id`的阶段只能`setup→progress→payoff`向前，且只能有一个payoff拥有者。上一段只把勺抬到唇前，下一段才允许入口点头；两段都点头属于重复兑现并阻断。每拍`caused_by`只能指向更早节拍，结尾必须用可见动作回答开头问题。

合同继续使用`schema_version=5`，并设置`director_core_version=7.3`、`director_plan_file=03_director_plan.json`。pre-visual前可以声明未来分镜路径，不能假装文件已存在；前置审稿通过只允许校准样张，不允许写生产表。schema3/4仅保留历史审计。复杂合同字段才读取[基础合同字段](references/replica_contract_schema.md)与[v5增量规范](references/creative_direction_v5.md)。

同时填写：

- `dialogue_requirements`：每个非静音Clip至少一条不可丢失关键句或关键词。
- `prop_continuity_requirements`：关键道具的出现、交接/使用和结果事件。
- `director_requirements`：结尾记忆点与人物“起点→转折→结果”表演弧。
- `finale_policy`：只能选`story_action`或`source_fact_card`。前者要求结尾动作/反应在最后3秒可见；后者只允许剧情答案先兑现，再用用户提供的真实事实图收尾，并锁定源文件与起止时间。
- `production_design`：记录产品参考资产及哈希、六项不可变特征、风格锁、音乐状态、运动类型，以及每个Pxx的起始状态→人物动作→产品动作→环境反应→运镜→速度变化→结束状态→转场触发→音乐卡点。

导演计划是创作者编写故事、镜头和连续性的唯一权威；合同保留校验器需要的机器字段，并用Sxx/Pxx与导演计划一一绑定，不得引入第二套剧情解释。用`product_visibility=visible/withheld_for_reveal`区分真实露出与延迟揭示。动态镜头必须通过“删除运镜后，人物或环境仍有明显运动”测试；复杂动作绑定起始、中间和结束关键帧。

按模式执行：

- 高保真视觉复刻：保留镜头顺序、时长比例、景别、机位、运镜、动作方向、转场、场景结构和光色。
- 爆款机制迁移：保留停留点、误判路径、权力变化、反转层级、因果升级和结尾记忆点，不要求逐镜画面相似。
- 商业混合复刻：有视频源时0至3秒重构商业冲突，之后遵循原片视觉节拍；静态插画源时全片时序原创，保留画法、色彩、空间组织和活动密度，不伪造原片时序。

不得额外套用其他模式的验收规则。

## 阶段五：按原片因果链写逐秒脚本并动态分段

先完成整条逐秒脚本，再在台词和因果不断的位置拆Clip，每段1至15秒连续覆盖全片。脚本只把`03_director_plan.json`转成易读台词和调度，不另发明剧情。每段默认最多3个可执行单元、2个有声回合、1行主商品事实；超出就拆Clip。只有同一模型、相近时长和复杂度的真实成片证据已核验时，才能上调容量并绑定证据。主体动作复杂时拆镜，不删热闹群像。

脚本完成后立即运行自动解析，不再人工自报口播秒数、汉字数和节拍数：

```bash
python3 "${SKILL_DIR}/scripts/validate_director_core.py" "<项目目录>" --out "<项目目录>/07_director_core_validation.json"
python3 "${SKILL_DIR}/scripts/analyze_script.py" \
  "<项目目录>" --out "<项目目录>/07_script_analysis.json"
```

程序按4.2字/秒检查每句实际口播窗口及全片占比（剧情60%、蒙太奇75%、古诗92%）。schema5每句必须有全片绝对口播窗口；数字/Latin需`expected_text`与全中文`spoken_text`展开，不能漏计。一句跨Clip、窗口冲突、脚本时间断层都阻断。见v5规范。

商场名、门店名、价格、权益范围、日期与CTA属于商业事实音频，不能把逐字正确寄托在视频模型临场说对。脚本将它们设计为画外音或不依赖嘴型的旁白，使用可控TTS/真人配音后期合成；角色嘴型对白只承担冲突和表演。AI表返回的原生片先完成商业事实配音与混音，才登记为`09_delivery_manifest.json`的候选片段。随后双模型ASR必须在合同时间窗内逐字命中；“合肥”被说成“河北”、提前/延后到错误动作、额外重叠人声都要返工，不能以画面不错放行。

前三秒可以用经确认的利益与异常动作制造钩子，不机械禁止价格或免费试吃；不能用品牌清单替代故事。角色说“一元、免费、不用付钱、0元”时，同拍且最晚前4秒必须有`commercial_truth_cues`，由后期准确叠字、可控旁白或真实事实卡限定参与条件；没有限定就阻断。结尾先兑现故事，再决定是否用1至2秒真实事实卡（最多2.5秒），不让模型乱写商品文字。

## 阶段六：人物设定与独立分镜图

在第一次生图前完整读取当前 Codex 环境已安装的 `imagegen` 技能说明，默认使用内置 `image_gen`，不擅自切换CLI/API。

1. 先取得`pre-visual → allow_visual_tests`，生成一张新构图的完整场景母样和一张人物细节校准图；实际传入原图作画法参考，保留调用证据。六轴与原图并排比较，不通过只迭代样张。用户要求先看风格时在此等确认。
2. 母样通过后才批量生成统一人物设定和分镜；人物图锁身份，母样锁风格，各自角色分明，不把一页低质量人物设定传染给全片。
3. 每个分镜单独调用一次生图；禁止用九宫格、漫画分栏或拼贴代替独立分镜。
4. 每张图保存到项目目录，并逐张检查人物、场景、道具、动作方向、说话对象、除白名单外无字幕/二维码/无关文字及9:16尺寸。
5. 相邻Clip输入的尾/首状态图保持同一状态，但这不是输出连续的证明。生成后必须查看实际最后编码帧与下一段首帧；主角或群众复制、持物倒退、摊位/食物/陈设增减、完成动作重演、运动方向跳变均需返修。
6. 用户指定扇面、招牌、包装等必须出现准确文字时，只允许该白名单文字；在生图提示词中逐字写明、生成后用`view_image`真实查看，确认不镜像、不错字，再写入合同的`visual_text_requirements`。此时禁止继续使用“画面无任何文字”这种冲突限制。
7. 复杂动作分别生成起始、中间和结束关键帧；参考资产只锁身份、产品和状态，不得把人物姿势锁死。关键帧只作为视频模型输入，不得直接当成最终动态镜头。

每张分镜必须绑定镜头ID、时间点、对标时间码、画面目的、景别/机位/构图、动作三态和生图提示词。

## 阶段七：Seedance提示词

每个片段输出一个可整段复制的代码块，包含画幅、精确时长、产品锁、风格`lock_id`与完整可复用风格提示词、参考图作用、逐秒镜头、动作、对白对象、普通话嘴型同步、首尾连续性和负面限制。

提示词开头必须逐个列出本段实际附件文件名和作用；正文每个`Pxx`再次写对应分镜文件名。不得只写“参考附件”。如果使用原片音乐或音效，合同必须分别记录原片截取区间和目标片使用区间，提示词必须写音频文件名、目标开始/结束时间和“不换其他音乐”。“原片同段BGM”不能代替文件名。

除合同白名单指定文字外，画面不得生成字幕、英文、二维码和无关信息。高保真和商业混合模式按镜头ID写明顺序、时长、机位、运镜、动作方向和转场；机制迁移的高密度档先给逐秒节拍表，再以相同顺序写入提示词。

每个`Pxx`必须逐项复述合同中的运动链：起始状态、人物连续动作、产品运动、环境反应、摄影机空间运动、速度变化、结束状态、动作触发转场和音乐卡点。单镜头只设一个主要人物动作和一个主要摄影机运动；人物动作复杂时简化运镜，运镜复杂时简化人物动作。禁止用摄影机推拉、数字缩放、背景替换或快速切换冒充动态事件。

## 阶段八：可选AI表交付

先刚性执行：只有本轮重新运行官方总门禁取得`pre-generation / status=ok / decision=allow_generation`且用户授权写表，才能写生产表。`allow_visual_tests`、`audit_only`、自写静态检查脚本、报错后附“草稿/待审核”都不是授权；不得删除错误再写，也不得把状态说明塞进生成提示词。任何脚本/图/提示词变动后重跑，比较`input_fingerprint`。门禁不能技术拦截所有外部写入，执行者必须遵守。

只有用户明确要求写入AI表时才执行。先使用钉钉技能读取真实Base、子表、字段和目标记录，把自动视频、公式、成本和生成结果字段加入合同`aitable_handoff.protected_field_ids`。写入只允许提示词和附件字段；每条记录人物图、分镜图、音频和商品素材合计最多9个附件，必须先为人物图和音频预留名额，再决定分镜数量。更新附件时先回读当前附件并做完整保留式替换，禁止只提交新增文件导致旧附件丢失。每条记录写后必须回读：提示词引用、附件文件名/数量、受保护字段的原值都要保持；不得顺手点击生成按钮。用户明确要求生成后，逐条回读`记录ID→Clip ID→结果文件/链接→实际时长→分辨率→完成状态`，下载后只能按合同的Clip时间顺序合片，不能按下载时间或表格行位置排序。

## 阶段九：验证后交付

使用 [templates/生成前质检表.md](templates/生成前质检表.md) 完成内容质检，再运行生成前总门禁：

```bash
python3 "${SKILL_DIR}/scripts/run_quality_gate.py" \
  "<项目目录>" --stage pre-generation \
  --out "<项目目录>/07_quality_gate_pre_generation.json"
```

分两层：`pre-visual → allow_visual_tests`只允许校准生图；`pre-generation → allow_generation`才允许完整生产交付/写表，并仍服从用户权限。总门禁执行资产、脚本与独立创意/美术证据检查。`--audit-legacy`只读旧包，结果最多`audit_only`，不得换脚本过滤报错通行。

用户明确要求使用VidMuse完成生成、剪辑和导出时，只有在这里取得`allow_generation`后才进入[VidMuse完整制作分支](references/vidmuse_full_production.md)。该分支必须先实时读取账号、积分、可用模型和生成参数，再计算包含问题镜头重生额度的预算；不得仅根据本文或历史记录假定模型名、价格、时长和时间线能力。没有明确生成请求时在此停止。

生成后完整读取[生成后质量清单规范](references/quality_gate_manifests.md)。按合同顺序建立`09_delivery_manifest.json`，对实际片做Watch固定时间线、双ASR、故事/表演/道具与跨段连续审查，再运行：

```bash
python3 "${SKILL_DIR}/scripts/run_quality_gate.py" \
  "<项目目录>" --stage pre-stitch \
  --delivery-manifest "<项目目录>/09_delivery_manifest.json" \
  --asr-manifest "<项目目录>/10_asr_manifest.json" \
  --director-manifest "<项目目录>/11_director_qc.json" \
  --out "<项目目录>/12_quality_gate_pre_stitch.json"
```

只有`allow_stitch`才能合片。缺段/错序、口播错时、故事动作不可见、道具跳变、人物或群众复制、前三秒钩子弱、长静止、重复兑现或结尾未收束均阻断。高保真模式另运行：

```bash
python3 "${SKILL_DIR}/scripts/validate_render.py" \
  "<原片>" "<成片>" --out "<项目目录>/质检/render"
```

每段时长误差不超过0.5秒。合片后必须对最终MP4重新运行`prepare_reference.py`，不得拿分段ASR冒充合片ASR；建立SHA绑定的`13_final_manifest.json`并运行：

```bash
python3 "${SKILL_DIR}/scripts/run_quality_gate.py" \
  "<项目目录>" --stage pre-publish \
  --delivery-manifest "<项目目录>/09_delivery_manifest.json" \
  --asr-manifest "<项目目录>/10_asr_manifest.json" \
  --director-manifest "<项目目录>/11_director_qc.json" \
  --final-manifest "<项目目录>/13_final_manifest.json" \
  --out "<项目目录>/14_quality_gate_pre_publish.json"
```

只有`allow_publish`才能称“可发布”。双模型ASR不一致时必须由真实听过成片的人复核；模型不能替人填写`human_audio_qc`。高保真模式额外传`--render-validation`。

## 成片复盘边界

用户提供AI表生成片段时，先按记录ID取回所有实际结果，登记SHA/时长/画幅，对每段实际MP4做双ASR及完整0.5秒逐张查看，再补看前三秒、转折与实际首末帧；不得等用户再次提醒才看。用户只有片段时运行pre-stitch，不假称已有最终合片。比较“原参考/输入图/提示词/实际画面/实际ASR”，逐项标明偏差最早发生阶段、证据时间、影响、返修及重验条件。真正合片后才运行pre-publish。未真实听音就明确音色/配乐未人工验收。
